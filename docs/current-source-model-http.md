# Current-source model startup: execution and evidence support

The current source-tree launcher was exercised on Windows with cached CPU BGE, generation disabled and an optional statement snapshot. The corrected observation attempt completed its startup and HTTP contract checks. Two quarterly Net income questions nevertheless received unsupported annual-report passages. **Operational execution passed; financial quality did not.**

The [sanitized diagnostic](acceptance/current-source-model-http-20261013.json) binds both actual attempts to source revision `06b319e3e40c37fbf5cbc55670b044456920d608`. These are already exposed development questions, not an independent evaluation set.

## What ran

The isolated interpreter used `-I -B` and an explicit snapshot of the current 20 package modules plus unmodified `run_api.py`. The existing semantic environment supplied dependencies; its historical installed package and vector-bound wheel were preserved. Fourteen package modules actually loaded from the snapshot, with exact Git source hashes.

The launcher retained CPU `BAAI/bge-small-en-v1.5` at revision `5c38ec7c405ec4b44b94cc5a9bb96e735b38267a`, threshold `0.78`, Top K `5`, generation `none` and its existing annual routing. It consumed the existing ten-report, 3,240-chunk corpus and `[3240, 384]` passage vectors. Offline cache-only settings and disabled implicit Hugging Face credential lookup were explicit. No installation or new passage embedding build occurred.

The repaired attempt observed one concrete SentenceTransformer constructor entry/return pair before listening and three concrete encode entry/return pairs across the three query requests. The passive observer changes no production functions or arguments. Return observations, together with accepted HTTP completion, establish this bounded execution path; they do not measure model accuracy or native performance.

Sixteen complete HTTP responses were retained: readiness, health, hidden docs, four authentication/validation controls, three dense queries and six statement requests. The ordinary query route returns 401 for an unauthorized valid JSON body, but malformed `application/json` returns 422 because framework parsing precedes its authentication dependency. The separate statement route authenticates before its manual body parser and returns 401 for the unauthorized malformed body.

## Preserve the failed observation attempt

The first attempt completed the same HTTP workload but remained **failed**: its model observation file was absent. Sentence Transformers 5.7.0 exports its implementation from `sentence_transformers/sentence_transformer/model.py`; the old callback matched a nonexistent `SentenceTransformer.py` path. Zero observed calls were an instrumentation error, not evidence of zero model activity.

A new task directory corrected only the passive predicate and bound the inspected library implementation/export bodies. AST-only controls replaced method bodies with `pass`: the original callback missed them, while the corrected callback counted the constructor and three encodes and excluded unrelated classes, functions, files and events. Neither control imported a model. The original protocol, failed receipt and complete HTTP records remain intact.

The repaired attempt rechecked 73 frozen inputs, 21 source snapshot files, five harness/control files and dependency metadata after teardown. All retained identities were unchanged. Owned launcher/native processes and the loopback listener closed. Forced termination did not produce a child-final record; no graceful shutdown or exit-time module-origin claim is made.

The similarity gate then accepts a superficially related annual overview. The current evidence-only `can_answer` and `evidence_passed` flags both describe that software gate; the returned answer remains empty. They are not financial correctness verdicts. Ordinary responses also have `provenance: null` for this legacy manifest; offline byte binding does not add publisher metadata to the wire response.

The separate statement route uses the same original source inputs with explicit document IDs. Its six complete responses match the preserved exposed source results except for request ID: three source candidates, one clarification, one refusal and one unsupported currency outcome. ## Next acceptance gate

Integrate a source-bound annual/quarter report catalog into model retrieval, distinguish report identity from financial column dates/durations, and repeat the same frozen questions without lowering the gate or rewriting inputs. Contradictory, unavailable or ambiguous scopes need explicit outcomes. A valid quarterly positive case must show that quarterly support is implemented, rather than blanket refusal. Candidate scope, exact field support, generated answer quality and consumer-facing status semantics require separate checks.

Independent human gold, held-out evaluation, generation, hosted API operation, TLS, tenant authorization, browser-to-API integration, performance distributions and observed Dot reproduction remain unaccepted. This source-snapshot run is separate from installed-wheel acceptance and from the earlier 35-row experiment, whose routing differed.
